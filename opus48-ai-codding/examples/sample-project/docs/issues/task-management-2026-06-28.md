## Issue 详情

### Issue 1：用户可以创建任务并看到在列表中

**标签**：enhancement, HITL, P0
**依赖**：无
**对应 PRD**：故事 1 + 故事 2

**目标**：
用户可以创建一个任务（只传标题），然后在任务列表中看到它。
这是曳光弹：最小但端到端，验证整条链路。

**验收标准**：
- [ ] 调用 `createTask("买牛奶")` 可以创建任务
- [ ] 调用 `getTasks()` 可以看到刚创建的任务
- [ ] 任务有唯一 ID
- [ ] 任务状态是 `todo`
- [ ] 任务优先级是 `medium`（默认）
- [ ] 任务列表按创建时间倒序排列

**实现指南**：
1. 先写测试（TDD）
2. 实现最简单的版本
3. 不要过度设计
4. 通过公开接口测试

**参考**：
- [PRD](../prd/task-management-2026-06-28.md)
- [CONTEXT.md](../../CONTEXT.md)

### Issue 2：用户可以更新任务状态

**标签**：enhancement, AFK, P1
**依赖**：Issue 1
**对应 PRD**：故事 3

**目标**：
用户可以更新任务的状态，从 `todo` 到 `in-progress`，再到 `done`。

**验收标准**：
- [ ] 可以把任务从 `todo` 改成 `in-progress`
- [ ] 可以把任务从 `in-progress` 改成 `done`
- [ ] 可以把任务从 `todo` 直接改成 `done`
- [ ] 改成无效状态会报错
- [ ] 状态更新后，`getTasks()` 会看到新状态

**实现指南**：
1. 复用 Issue 1 的代码结构
2. 封装状态机逻辑在 `Task` 模块内
3. 通过公开接口测试

**参考**：
- [PRD](../prd/task-management-2026-06-28.md)
- [CONTEXT.md](../../CONTEXT.md)（状态机规则）

### Issue 3：用户可以删除任务

**标签**：enhancement, AFK, P1
**依赖**：Issue 1

### Issue 4：用户可以按优先级筛选任务

**标签**：enhancement, AFK, P2
**依赖**：Issue 1
**对应 PRD**：故事 4

**目标**：
用户可以只看某个优先级的任务。

**验收标准**：
- [ ] `getTasks({ priority: "high" })` 只返回高优先级任务
- [ ] `getTasks({ priority: "medium" })` 只返回中优先级任务
- [ ] `getTasks({ priority: "low" })` 只返回低优先级任务
- [ ] `getTasks()` 不传筛选返回所有

**实现指南**：
1. 给 `getTasks()` 加一个可选的 `filter` 参数
2. 保持接口简单

**参考**：
- [PRD](../prd/task-management-2026-06-28.md)
