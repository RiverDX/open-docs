# PRD：任务管理系统

> 创建：2026-06-28
> 基于：CONTEXT.md + Grill 对话

---

## 问题陈述

- **我们解决什么问题？**：用户需要一个简单的工具来管理任务，记录要做的事、跟踪进度
- **为谁解决？**：个人用户（第一版不做多用户）
- **成功是什么样？**：用户可以快速创建任务、更新状态、看到所有任务

---

## 解决方案概要

- **一句话说清楚我们做什么**：一个简单的任务管理系统，支持 CRUD 操作，内存存储
- **为什么选这个方案？**：根据 ADR-002，先做内存存储验证核心逻辑，再加数据库

---

## 用户故事

### 故事 1：作为用户，我可以创建任务，以便记录要做的事

**验收标准**：
- [ ] 可以只传标题创建任务
- [ ] 可以传可选的描述
- [ ] 可以传可选的优先级（默认 medium）
- [ ] 创建后任务状态是 `todo`
- [ ] 任务有唯一 ID

**不做**：
- 任务截止日期（范围外）
- 任务标签（范围外）

### 故事 2：作为用户，我可以查看任务列表，以便知道有什么事

**验收标准**：
- [ ] 可以看到所有任务
- [ ] 每个任务显示标题、状态、优先级
- [ ] 任务按创建时间倒序排列（最新的在最前）

**不做**：
- 搜索功能（范围外）
- 筛选功能（除了优先级，见故事 4）

### 故事 3：作为用户，我可以更新任务状态，以便跟踪进度

**验收标准**：
- [ ] 可以把任务从 `todo` 改成 `in-progress`
- [ ] 可以把任务从 `in-progress` 改成 `done`
- [ ] 可以把任务从 `todo` 直接改成 `done`
- [ ] 不能改成无效的状态（会报错）

**不做**：
- 状态回退（比如从 `done` 改回 `todo`，第一版不支持）

### 故事 4：作为用户，我可以按优先级筛选任务，以便看到重要的事

**验收标准**：
- [ ] 可以只看 `high` 优先级的任务
- [ ] 可以只看 `medium` 优先级的任务
- [ ] 可以只看 `low` 优先级的任务

**不做**：
- 多条件筛选（范围外）

### 故事 5：作为用户，我可以删除任务，以便清理不需要的

**验收标准**：
- [ ] 可以删除指定 ID 的任务
- [ ] 删除后任务列表里就没有了
- [ ] 删除不存在的任务会报错

**不做**：
- 软删除（第一版硬删除）

## 主要模块设计

> 寻找深模块：简单接口，丰富实现

### 模块 1：Task

- **职责**：管理任务的 CRUD 操作，封装状态机逻辑
- **接口**（简单）：
  - `createTask(title, description?, priority?)`
  - `getTasks(filter?)`
  - `updateStatus(taskId, newStatus)`
  - `deleteTask(taskId)`
- **隐藏的复杂性**（丰富）：
  - 状态机规则（哪些状态转换允许）
  - ID 生成
  - 任务存储
  - 按优先级筛选
- **相关文件**：`src/models/Task.js`

## 测试策略

- **单元测试**：覆盖所有用户故事，通过公开接口测试
- **集成测试**：本版本暂不做
- **不测试**：不测试私有方法，只测试公开行为

**测试用例规划**：
1. 创建任务（正常路径）
2. 创建任务（只传标题）
3. 创建任务（带优先级）
4. 创建任务（无效优先级）
5. 查看任务列表
6. 更新状态（todo → in-progress）
7. 更新状态（in-progress → done）
8. 更新状态（todo → done）
9. 更新状态（无效状态）
10. 按优先级筛选
11. 删除任务
12. 删除不存在的任务

- [待验证] 用户只需要简单的 CRUD，不需要复杂功能 —— 如果错了，后续迭代再加

## 风险

- **风险 1**：内存存储重启后数据丢失 —— 缓解措施：这是第一版，故意的，后续加持久化
- **风险 2**：用户需要更多功能 —— 缓解措施：先上线核心，根据反馈迭代
